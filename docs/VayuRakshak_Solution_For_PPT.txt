1. ONE-PARAGRAPH SUMMARY
================================================================================
VayuRakshak (AeroTwin-AI) is a sovereign, air-gapped maintenance decision
platform for military aircraft. It combines physics-based degradation indicators,
gradient-boosted Remaining Useful Life (RUL) prediction, a 3D digital twin,
depot/spares logic, and mission-fit dispatch in one web console. The system is
designed to predict component failure early enough to pre-position the right
spare, inspect the right subsystem, and assign the right airframe before an
Aircraft On Ground (AOG) event occurs.


================================================================================
2. WHAT THE PLATFORM DOES
================================================================================
The working prototype has seven console tabs plus a work-order requisition modal.

2.1 Fleet Command
    - Shows MC / FMC / PMC / AOG counts and rates.
    - Filters by airbase and aircraft status.
    - Surfaces critical AOG and PMC alerts.
    - Shows per-aircraft health bars and remaining life.

2.2 3D Digital Twin
    - Three.js WebGL model of the fighter airframe.
    - Exploded subsystem view and thermal/stress heatmap mode.
    - Subsystem inspector for engines, hydraulics, avionics/radar and airframe.
    - Live EGT, vibration, hydraulic pressure and wear readouts.

2.3 Predictive AI (RUL)
    - Point RUL estimate in flight hours.
    - 10th and 90th percentile confidence bounds.
    - Degradation trajectory and AOG redline.
    - SHAP-style sensor attribution (T50, P30, core vibration, bypass ratio).
    - Action recommendation and risk category.

2.4 Depot & Spares
    - IMMOLS-style spares catalog with NSN codes.
    - e-MMS-style work orders with priority, depot, ETA and authorizing officer.
    - Lead-time-vs-RUL deficit alerts: if part lead time > remaining life, raise
      an AOG-prevention alert.
    - Requisition modal that creates a new work order.

2.5 Anti-Cannibalization Matrix
    - Evaluates donor airframes of the same type.
    - Scores donor feasibility by status, same-base availability, swap time and
      depot replenishment time.
    - Flags whether borrowing a part would ground an active FMC aircraft.

2.6 Mission Dispatch
    - Mission profiles: QRA Scramble, Combat Air Patrol, Deep Penetration
      Strike, Tactical Recon / Ferry.
    - Each profile has gates for status, RUL, fatigue index and subsystem health.
    - Ranks eligible aircraft and labels priority allocation / reserve /
      not recommended.

2.7 Raksha-Mitra Assistant
    - Air-gapped IETM/SOP retrieval for four fault families:
      EGT overheat, core vibration, hydraulic pressure decay, MIL-STD-1553 bus
      parity errors.
    - Returns fault code, severity, step-by-step SOP, required tools and TAT.
    - This is deterministic keyword/fault-code matching over a curated knowledge
      base. It is not a cloud LLM.

2.8 Validation & What-If
    - Displays NASA C-MAPSS-style benchmark metrics.
    - What-if simulator for combat afterburner overheat, desert dust ingestion
      and high-G dogfight scenarios.
    - Fleet CSV export.

5. MACHINE-LEARNING MODEL - DETAILED
================================================================================
5.1 Problem type
    Supervised regression: predict Remaining Useful Life (RUL) from current
    engine/airframe sensor state.

5.2 Data
    - The training script uses a deterministic, high-fidelity synthetic
      NASA C-MAPSS FD001-profile generator.
    - 120 engines, seed 42.
    - Each engine follows a run-to-failure trajectory:
      healthy plateau, then Weibull/exponential wear in HPC/HPT temperature,
      pressure and bypass ratio until failure at RUL = 0.
    - Each row contains 3 operational settings and 21 sensor channels.
    - This lets the demo run offline and reproducibly. It is NOT the recorded
      NASA FD001 file set. A real FD001 loader is a roadmap item.

5.3 Target
    - RUL is clipped at 125 cycles (standard piecewise upper limit).
    - This focuses learning on the degradation zone instead of the long healthy
      plateau.

5.4 Train/test split
    - Split by engine unit, not by cycle, to prevent leakage.
    - 75% / 25% split.
    - 120 engines -> 90 training engines, 30 held-out test engines.
    - 7,693 test cycles evaluated.

5.5 Models
    - Point estimate:
      HistGradientBoostingRegressor
      max_iter=150, learning_rate=0.08, max_depth=7, random_state=42
    - Lower bound:
      HistGradientBoostingRegressor
      loss="quantile", quantile=0.10,
      max_iter=100, learning_rate=0.08, max_depth=6, random_state=42
    - Upper bound:
      HistGradientBoostingRegressor
      loss="quantile", quantile=0.90,
      max_iter=100, learning_rate=0.08, max_depth=6, random_state=42

5.6 Inference output
    - Point RUL in cycles.
    - q10 and q90 RUL bounds.
    - Conversion to flight hours: cycles x 1.4 h/cycle.
    - Risk tiers based on predicted hours:
        <= 15 h or AOG status  -> CRITICAL_AOG / ground immediately
        <= 45 h or PMC status  -> HIGH_WATCH / restrict combat, pre-order spares
        <= 80 h                -> ELEVATED / monitor trend
        > 80 h                 -> NOMINAL / cleared
    - Degradation trajectory for the chart.
    - SHAP-style feature attribution for root-cause explanation.

5.7 Validation metrics (benchmark_metrics.json)
    - Test MAE: 9.13 cycles
    - Test RMSE: 13.20 cycles
    - R-squared: 0.893
    - 10th-90th percentile band coverage: 91.4%
    - NASA PHM score: 22,692.15
    - Held-out test engines: 30
    - Held-out test cycles: 7,693

    MAE by remaining-life window:
      0-25 cycles:   3.86 cycles
      25-50 cycles: 10.19 cycles
      50-75 cycles: 15.99 cycles
      75-125 cycles: 15.96 cycles

    Note: the validation console's lead-time cards currently show an older
    hardcoded run (4.12 / 6.78 / 8.95 / 12.10). The benchmark JSON values above
    are the source of truth. Refresh those cards before the final demo if the
    numbers must match exactly.

5.8 Explainability
    - The console shows contributions for:
        T50 / sensor s4 (turbine outlet EGT)
        P30 / sensor s7 (HPC outlet pressure)
        core vibration
        bypass ratio / sensor s15
    - This is a deterministic, SHAP-style engineering attribution model, not a
      call to the SHAP library. Say "SHAP-style" in the presentation, not
      "SHAP values from the SHAP package".

5.9 Fallback behavior
    - If the joblib artifacts are missing, model.py uses a calibrated wear-index
      surrogate based on T50, P30, PS30 and BPR so the demo still returns a
      prediction.
    - The fallback is a demo-resilience feature, not the primary model.

5.10 Known limitations
    - Synthetic C-MAPSS-profile data, not recorded FD001 files.
    - No live sensor feed or flight-qualified calibration yet.
    - Model is a decision-support prototype, not a certified airworthiness tool.

6. PHYSICS ENGINE
================================================================================
The physics layer turns raw telemetry into interpretable engineering indicators.

6.1 EGT margin
    EGT_margin = max(0, 880 - EGT_actual)
    880 C is the modeled maximum continuous redline.
    A shrinking margin indicates turbine creep and thermal degradation.

6.2 HPC isentropic efficiency
    eta = (p30/p24)^((gamma-1)/gamma) / (T30/T24)
    gamma = 1.4
    The drop is measured against a nominal efficiency of 0.885.

6.3 Vibration
    Fan and core RMS are tracked with 1X/2X rotor harmonics.
    Modeled thresholds:
      Fan:  1.5 / 2.8 / 4.5 mm/s
      Core: 2.0 / 3.5 / 5.5 mm/s

6.4 Structural fatigue
    D = sum( delta_G^3.2 / 1.5e5 ) for delta_G > 1.5
    Simplified rainflow cycle counting with Palmgren-Miner cumulative damage.

6.5 Subsystem health index
    Weighted overall health:
      40% propulsion
      25% hydraulics
      20% avionics
      15% airframe
    Five subsystem groups are rendered in the 3D twin:
      port engine, starboard engine, hydraulics, avionics/radar, airframe.

6.6 Telemetry simulation
    Four flight phases:
      TAKEOFF, COMBAT_MANEUVER, COMBAT_CRUISE, DESCENT_APPROACH
    Each phase sets altitude, Mach, throttle, G mean and G spread.
    Degradation scales EGT, vibration, hydraulic pressure, oil pressure,
    oil temperature, bus error rate and G-load.

7.3 Spares
    - 5 NSN-coded items:
        AL-31FP HPC Stage 3 blade kit
        Digital hydro-mechanical fuel metering unit (FMU)
        Fly-by-wire hydraulic actuator
        MIL-STD-1553B dual-redundant bus interface unit
        Turbine EGT thermocouple harness assembly
    - Lead times: 12-36 hours.
    - Stock levels are tracked in the prototype.

7.4 Work orders
    - e-MMS-style IDs, tail number, priority (P1 AOG / P2 PMC), status,
      part needed, depot, destination base, ETA and authorizing officer.
    - Creating a requisition deducts stock if available and inserts a new work
      order at the top of the list.

7.5 IETM knowledge base
    - Four fault families:
        EGT overheat / margin deterioration
        Core shaft vibration / bearing harmonics
        Hydraulic pressure decay / actuator lag
        MIL-STD-1553B bus parity / timeout
    - Each has symptoms, four SOP steps, tools and estimated TAT.

7.6 Mission profiles
    - QRA Scramble: 9.0 G, FMC required, min 25 h RUL, max fatigue 0.85.
    - Combat Air Patrol: 8.0 G, FMC required, min 30 h RUL, max fatigue 0.80.
    - Deep Penetration Strike: 7.5 G, FMC required, min 40 h RUL, max fatigue 0.75.
    - Tactical Recon / Ferry: 4.5 G, PMC allowed, min 15 h RUL, max fatigue 0.92.

7.7 Integration stance
    - Data contracts are modeled on IAF e-MMS, IMMOLS and BRD workflows.
    - The current build uses simulated records and in-memory Python structures.
    - It is a working prototype, not a live depot connection.
    - Production next step: database-backed store + real connectors + auth/RBAC.

9. VALIDATION AND BENCHMARK SCOPE
================================================================================
What the benchmark does:
  - Generates 120 C-MAPSS-profile engines.
  - Clips RUL at 125 cycles.
  - Splits 75/25 by engine unit.
  - Trains point + q10 + q90 models.
  - Evaluates MAE, RMSE, R-squared, NASA PHM score and quantile coverage.
  - Breaks MAE down by remaining-life window.

What the current numbers mean:
  - 9.13 cycles MAE overall.
  - 3.86 cycles MAE in the final 0-25 cycle window (highest precision near
    failure).
  - 91.4% of true RUL values fall inside the q10-q90 band, above the 80% target.
  - 30 held-out engines and 7,693 test cycles.

Claim boundary (important for judges):
  - These are benchmark results on a controlled, synthetic C-MAPSS-profile
    dataset, not on recorded FD001 files or live squadron telemetry.
  - The model is a working prototype, not flight-certified.
  - The next step is a real FD001 loader and field calibration.

Reproduce:
  cd backend
  python -m app.train
  python -m pytest tests/test_vayurakshak.py -q

Current test result: 12 passed.
