01 · The operational problem

Availability is lost between the aircraft and the depot.

Military air fleets lose mission-capable hours to disconnected data, reactive maintenance and parts that arrive after the aircraft is already grounded. The platform targets the full closed loop — sense, predict, sustain and employ.

01

Data is fragmented

FDR/HUMS telemetry, MIL-STD-1553B avionics buses, paper/e-MMS logs and depot inventory live in separate silos.

No single airframe truth
02

Maintenance is reactive

Fly-to-failure or rigid calendar TBO means components are replaced too late, or pulled too early with life remaining.

Condition is not the trigger
03

AOG creates cannibalization

When a spare's depot lead time exceeds the component's remaining life, crews strip parts from other jets to keep one flying.

One snag grounds two airframes
04

Dispatch is health-blind

Sortie allocation rarely considers fatigue index, subsystem health or RUL, so high-stress missions can go to the wrong airframe.

Mission mismatch
→
Design goal: predict degradation early enough to position the right spare, inspect the right subsystem and assign the right aircraft — before an AOG event occurs.

05 · Machine-learning model

Three gradient-boosted models, one calibrated RUL envelope.

The model predicts Remaining Useful Life in cycles, converts it to flight hours and reports a 10th–90th percentile band so maintainers can plan for the pessimistic case, not just the average.

1

Data generation

Deterministic C-MAPSS FD001-profile run-to-failure harness: 120 engines, seed 42, healthy plateau followed by Weibull/exponential wear. Each row has 3 settings + 21 sensors.

2

Target definition

RUL is clipped at 125 cycles (piecewise upper limit) so the model learns the degradation zone rather than an unbounded healthy plateau.

3

Engine-level split

75 / 25 split by engine, not by cycle. This gives 30 held-out engines and 7,693 test cycles with no cycle leakage.

4

Model family

scikit-learn HistGradientBoostingRegressor: point model (150 iterations, lr 0.08, depth 7) and quantile models q10/q90 (100 iterations, lr 0.08, depth 6).

5

Inference output

RUL cycles × 1.4 h/cycle → flight hours; risk tiers NOMINAL / ELEVATED / HIGH / AOG; trajectory and SHAP-style sensor attribution.

06 · Physics engine & digital twin

Physics gives the limits. ML learns the wear.

The physics layer turns raw telemetry into interpretable engineering indicators, then the digital twin places those indicators on the airframe so a maintainer can see where the problem is.

EGT margin

EGT_margin = max(0, 880 − EGT)
A shrinking margin is the primary physical signal of turbine creep and thermal degradation.

HPC efficiency

η = (p30/p24)^((γ−1)/γ) / (T30/T24)
γ = 1.4; drop is measured against a nominal 0.885 efficiency.

Vibration harmonics

Fan and core RMS are tracked with 1X/2X rotor harmonics. Thresholds: 1.5 / 2.8 / 4.5 mm/s for fan; 2.0 / 3.5 / 5.5 mm/s for core.

Fatigue index

D = Σ(ΔG^3.2 / 1.5e5) for ΔG > 1.5; simplified rainflow counting with Palmgren–Miner cumulative damage.

Live console: Three.js WebGL twin with exploded subsystems, heatmap mode, subsystem inspector and telemetry readouts.

Subsystem health index

Weighted overall health: 40% propulsion, 25% hydraulics, 20% avionics, 15% airframe. Five groups are rendered: port/starboard engines, hydraulics, avionics/radar and airframe structure.

✓
Hybrid rationale: physics provides fast, interpretable redlines and simulation; the ML model learns non-linear wear patterns from run-to-failure histories. Neither is used alone.

10 · Deployment, security & roadmap

Built to run inside the station, not in the cloud.

The current prototype runs entirely locally. The roadmap is about connecting it to real maintenance systems — not replacing the model with a hosted service.

Deployment posture

Local/air-gapped execution; FastAPI serves the API and the built SPA from one process. start.bat trains missing models, builds the UI if needed and launches Uvicorn. No cloud ML, no external LLM, no paid API.

Security & data notes

Demo data is in-memory and resets with the process. CORS is open for local development; production requires restricted origins, authentication/RBAC, audit logging and a database-backed store. These are deliberate next-step items, not hidden claims.

Verified in the build

12 backend tests cover fleet, dossier, telemetry, twin, quantile ordering, logistics, work orders, cannibalization, dispatch, assistant, what-if and CSV export. The frontend builds with Vite.

Phase 1 · 0–3 months

Integrate

e-MMS/IMMOLS sandbox, ground-test rig feed, real NASA FD001 file loader, field sensor calibration.

Phase 2 · 3–6 months

Field trial

Selected Su-30MKI / Tejas squadron, maintainer feedback loop, threshold tuning, reliability tracking.

Phase 3 · 6–12 months

Depot rollout

3 BRD / 11 BRD / 7 BRD deployment, RBAC and audit, AFNet hardening, full spares workflow.

!
Status: working prototype, not flight-certified. The ML, physics, logistics and dispatch engines are functional; live sensor and depot integrations remain roadmap items.
